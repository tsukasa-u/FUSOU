# Controlled Natural Capture Procedure v1

Status: procedure only. This document does not provide natural evidence and does not unblock P0-04 or P0-05.

## Scope

This procedure is for an authorized operator observing ordinary FUSOU-APP gameplay traffic. Natural capture is not a Game Server access feature. It must not be used to issue a standalone Game Server request, inject a request, replay a request, retry a forwarded logical request, or generate traffic.

The repository does not establish the ordinary gameplay action that first causes `require_info`. The trigger action remains `UNKNOWN` in the manual review record.

## Preconditions

- Use an authorized supported Game Client and an allowlisted Game Server.
- Use a private absolute capture directory outside the repository and outside tracked evidence directories.
- Keep capture disabled unless the operator is ready to observe one ordinary local session.
- Do not use an automated gameplay script, request generator, replay tool, or retry loop.
- Do not place credentials, cookies, tokens, private identifiers, or raw capture bytes in the repository.

## Collection

1. From the repository root, start the verification test-play launcher with a private absolute output directory:

	```text
	pnpm --dir packages/FUSOU-APP testplay:verify -- /absolute/private/capture-root
	```

	The launcher temporarily enables capture, disables API/resource persistence and asset upload for this session, starts `tauri dev`, and restores the exact previous development user config when the process exits. The default configuration remains disabled with an empty output path. Do not use a path inside the repository.
2. Start FUSOU-APP normally through that launcher. The APP starts the HTTPS proxy and PAC routing before opening the Game Client.
3. Use only ordinary Game Client startup and gameplay. Do not open a separate HTTP client, call the Game Server directly, or manually construct the `require_info` request.
4. Stop the session after the naturally observed `require_info` exchange. Do not retry the exchange if the capture is incomplete.
5. Disable capture again after the controlled session.

The collector is passive. It records client-facing TLS plaintext after MITM TLS accept and before Hyper parsing, preserves directional wire bytes and Hyper lifecycle message ranges, and writes an artifact only after a clean request/response lifecycle. It does not create upstream traffic.

## Candidate Verification

Run the read-only verifier against the private artifact:

```text
cargo run --manifest-path packages/FUSOU-PROXY/proxy-https/Cargo.toml --bin verify_capture -- /absolute/private/capture-root/capture-id
```

A successful result proves artifact integrity and collector policy only. It produces a `natural_candidate`, never `natural_provenance=true`.

## Manual Observation Record

Copy [tlsn-natural-capture-review-template-v1.json](tlsn-natural-capture-review-template-v1.json) outside the repository and fill it without adding raw payloads. The record must assert, from the operator's observation, all of the following:

- ordinary FUSOU-APP startup and ordinary gameplay were used;
- the request was generated by the existing Game Client;
- no standalone Game Server request, injection, replay, retry, or capture-generated traffic occurred;
- the client-facing TLS plaintext boundary was used;
- `require_info` was observed;
- the trigger action remains `UNKNOWN`;
- the raw artifact remains private and no raw artifact is committed;
- a sanitized fixture was separately reviewed for credentials and session tokens.

The record must copy the candidate's capture ID, complete artifact SHA-256, APP version, Game Client, and allowlisted Game Server identity exactly. Verify the external record with:

```text
cargo run --manifest-path packages/FUSOU-PROXY/proxy-https/Cargo.toml --bin verify_capture -- /absolute/private/capture-root/capture-id /absolute/private/natural-review.json
```

The verifier returns `natural_provenance=true` only as the result of matching the external manual record. It does not rewrite the capture manifest or mark the collector artifact as naturally authoritative.

## Raw-to-Sanitized Workflow

1. Keep the exact-wire artifact private and immutable. Record its complete artifact hash in the external review record.
2. Inspect the raw artifact manually. Treat HTTP headers, cookies, authorization values, body values, compression bytes, and identifiers as sensitive until reviewed.
3. Produce a separate sanitized fixture through an explicit, operator-controlled transformation. The existing sanitizer redacts selected byte values and credential-like headers on structured messages; it is not an automatic parser or an authorization step for exact-wire raw bytes.
4. Write the sanitized output as `SANITIZED_PENDING_REVIEW`. Review the resulting request and response bodies and headers manually.
5. Record the sanitized fixture ID and the privacy review only after confirming that credentials and session tokens are absent. Never copy the raw artifact into `docs/security/evidence/`.
6. Keep the raw artifact, completed review record, and any local sensitive review notes in private storage.

A sanitized fixture is not natural evidence by itself. A hash match is not a privacy review, and a privacy review is not TLSNotary verification.

## Stop Conditions

Discard the candidate from natural-evidence consideration when any of these occurs:

- a request was manually generated, injected, replayed, or retried;
- the session used a standalone Game Server access path;
- the capture was incomplete, malformed, or not client-facing plaintext;
- the allowlisted server, client, or APP version cannot be matched;
- raw secrets remain in the sanitized fixture;
- the operator cannot explain the provenance without inferring the unknown trigger action.

This procedure does not implement TLSNotary, a verifier, an authenticated disclosure, a database migration, or a production rollout. P0-04 remains `BLOCKED` until an authorized natural capture is manually obtained, and P0-05 remains `BLOCKED` until the separate authenticated disclosure and strict verifier evidence exist. `IMPLEMENTATION = NO-GO` remains unchanged.
